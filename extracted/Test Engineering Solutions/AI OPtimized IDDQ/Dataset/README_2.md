# Synthetic IDDQ Dataset for AI-Optimized Test Time

Synthetic data for developing and benchmarking the methods in *AI-Optimized IDDQ Test Time Reduction*: vector reduction, settling-time prediction, adaptive per-die test, outlier screening, spatial prediction and flow ordering.

All values are synthetic and generated by `generate_iddq_dataset.py` (seed 42). The models are simplified, but they preserve the relationships the methods depend on. Re-run with another seed for fresh data:

```
python3 generate_iddq_dataset.py --seed 7 --out ./run2
```

## Files

| File | Rows | Grain | Main use |
|---|---|---|---|
| `iddq_die_data.csv` | 32,400 | one die | Outlier screening, adaptive test, spatial models, escape/overkill evaluation |
| `iddq_transients.csv` | 30,000 | die × core vector (1,500 die) | Settling-time prediction |
| `vector_info.csv` | 20 | core vector | Test-time model, flow ordering |
| `vector_fault_matrix.csv` | 2,000 | modeled fault site | Vector reduction (set cover, GA, RL) |

## What is simulated

- **Population:** 12 lots × 5 wafers × 540 die. The wafer is a 28 × 28 grid clipped to a circle. Test is 4-site parallel on 2 testers at about 25 °C.
- **Process speed** drives leakage. Each die has a latent speed set by lot offset, wafer offset, wafer gradient, a radial bowl and random variation. Faster die leak more and show a higher ring-oscillator frequency, higher Fmax, lower Vmin and a higher leakage-monitor reading.
- **Leakage-only IDDQ:** core is log-normal with a median of about 170 µA (p5 to p95 is roughly 100 to 310 µA). The I/O rail is around 20 µA. Each vector has a fixed state-leakage factor, and edge die leak about 15% more.
- **Measurement effects:** temperature sensitivity is about 4.5% per °C. Site bias is site 2 +2%, site 3 −1% and site 4 +4%, so site 4 reads high. There is also absolute plus proportional noise.
- **Process shift:** LOT12 has a clear upward leakage shift, with a median of about 340 µA against 120 to 245 µA for other lots. It sits in the test split, so it checks drift handling and fixed-limit overkill.
- **Defects:** about 2.2% of die are defective, with a higher rate at the edge. The four types are:

| Type | Share | Signature in IDDQ | Downstream fail probability (final / burn-in / field) |
|---|---|---|---|
| `bridge` | 55% | Extra current (median 30 µA, wide spread) only on the vectors that activate its fault in `vector_fault_matrix.csv` | 0.40 / 0.15 / 0.05 |
| `gate_oxide_short` | 20% | Extra current on all vectors (median 40 µA); sometimes on I/O too | 0.30 / 0.40 / 0.10 |
| `open_floating` | 15% | Extra current on 1 to 3 vectors (median 20 µA) | 0.50 / 0.10 / 0.03 |
| `latent_weak` | 10% | Small current (3 to 15 µA) on about 30% of vectors; hard to see | 0.05 / 0.45 / 0.15 |

Clean die fail downstream at 0.1% (final), 0.05% (burn-in) and 0.01% (field).

## Baseline behaviour (seed 42)

These figures are measured on the generated data and give you a reference point.

| Screen | Defects caught (of 725) | Good die failed |
|---|---|---|
| Legacy fixed limit, core max > 450 µA (`fixed_limit_fail`) | 67 | 854, mostly in LOT12 |
| Max/min current ratio at the 99.5% good-die quantile | 415 | 159 |

The ratio screen catches most bridges (77%) and opens (56%), but few gate-oxide shorts (28%) or latent defects (21%). Uniform elevation needs a leakage-normalized residual or multivariate model, which is the gap the ML methods should close.

| `fixed_limit_fail` | 0/1 | Legacy screen result: core max > 450 µA |
| `final_test_fail` | 0/1 | Failed at final test |
| `burn_in_fail` | 0/1 | Passed final test, failed burn-in |
| `field_return` | 0/1 | Passed final test and burn-in, returned from the field |

**Labels.** `true_defect` is the oracle label, used for development and for measuring escapes. In real production you would only see downstream outcomes, so `final_test_fail`, `burn_in_fail` and `field_return` let you train on realistic, noisy labels. Split by lot, never by random die, as Section 6.4 of the document describes.

## Column dictionary: `iddq_transients.csv`

| Column | Unit | Description |
|---|---|---|
| `die_uid`, `vector_id`, `rail` | | Die, core vector (1 to 20), rail |
| `true_defect`, `suggested_split` | | Copied from the die table |
| `i_t0.1ms_ua` … `i_t2.0ms_ua` | µA | Supply current sampled every 0.1 ms after vector apply |
| `settled_iddq_ua` | µA | Fully settled value (target to predict); equals the die table value |
| `full_settle_time_ms` | ms | Wait the current program uses for this vector |

Waveforms are the settled value plus a fast and a slow decaying exponential plus noise. Time constants are set per vector, with small per-die variation. Defective die are oversampled to 20% so the model sees enough of them.

## `vector_fault_matrix.csv`

There is one row per modeled fault site (`fault_id` 0 to 1,999). Columns `v01` to `v20` are 1 when that vector activates the fault. About 12% of faults are caught by a single vector, so dropping vectors has a real coverage cost. Bridge and open defects in the die table use these rows, so a reduced vector set's coverage loss shows up directly as missed defective die.

## Suggested exercises

1. **Vector reduction.** Greedy set cover on the fault matrix, weighted by `full_settle_time_ms`. Then count which defective die in the test split would have been missed.
2. **Settling prediction.** Predict `settled_iddq_ua` from the first 3 to 5 samples with conformal intervals. Report the settling time saved at a set error bound.
3. **Outlier screening.** Regress expected IDDQ on ring oscillator, leakage monitor, position and site. Screen on the residual and compare against `fixed_limit_fail` and the ratio screen, including on LOT12.
4. **Adaptive test.** Train a risk model on pre-IDDQ features only, then pick a threshold with zero escapes on validation. Measure the reduced-flow share and escapes on test.
5. **Spatial prediction.** Fit a Gaussian process per wafer on a 20% die sample and predict the rest.
